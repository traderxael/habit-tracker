# Plan de proyecto — Software/Web (1 mes, tiempo completo)

**Periodo:** 28 de septiembre – 31 de octubre de 2026
**Dedicación:** tiempo completo
**Estado del proyecto:** idea por definir (se cierra en la Fase 0)

---

## Objetivo general

Definir una idea de proyecto web alcanzable y llevarla desde cero hasta un producto en línea y usable por otra persona, en cuatro semanas.

## Entregables del plan

| Entregable | Dónde | Cuándo |
|---|---|---|
| Este roadmap | `plan-proyecto.md` (workspace) | 28 sep |
| Copia consultable | QMind (fuente) | 28 sep |
| Idea y alcance cerrados | `idea-proyecto.md` | 29 sep |
| App en local | workspace | 6 oct |
| MVP completo | workspace | 20 oct |
| Proyecto desplegado + README | hosting elegido | 27 oct |

---

## Fase 0 — Definir la idea

**Fechas:** 28–29 sep (2 días)

- [ ] Proponer 3 ideas candidatas alcanzables en 1 mes a tiempo completo.
- [ ] Evaluar cada idea con estos criterios: motivación, alcance viable en 4 semanas, stack conocido vs. por aprender, utilidad real.
- [ ] Elegir una y escribir `idea-proyecto.md` con: problema que resuelve, usuarios, features del MVP y qué queda **fuera** de alcance.
- [ ] Definir el stack y la forma de despliegue.

**Hito:** idea única decidida y alcance por escrito.

## Fase 1 — Diseño y esqueleto

**Fechas:** 30 sep – 6 oct (semana 1)

- [ ] Arquitectura básica: vistas/páginas, modelo de datos, endpoints o funciones.
- [ ] Inicializar el proyecto (repo, estructura de carpetas, dependencias).
- [ ] Montar navegación y layout base sin lógica de negocio.

**Hito:** la app arranca en local y se puede navegar por el esqueleto.

## Fase 2 — MVP: features núcleo

**Fechas:** 7–20 oct (semanas 2 y 3)

- [ ] Listar las features del MVP en orden de valor.
- [ ] Implementarlas una a una, terminando cada una antes de empezar la siguiente.
- [ ] Integrar datos (base de datos o almacenamiento) a mitad de la semana 2.
- [ ] Probar manualmente cada feature al terminarla y corregir bugs en el momento.

**Hito:** el flujo principal funciona completo de punta a punta.

## Fase 3 — Pulido y despliegue

**Fechas:** 21–27 oct (semana 4)

- [ ] Estilos/UI coherentes.
- [ ] Estados de error, vacío y carga; casos borde.
- [ ] Desplegar/publicar el proyecto.
- [ ] README mínimo: qué es, cómo correrlo, dónde está publicado.

**Hito:** proyecto en línea y usable por otra persona.

## Buffer y revisión

**Fechas:** 28–31 oct

- [ ] Días colchón para imprevistos o tareas arrastradas.
- [ ] Retrospectiva corta: qué funcionó, qué no, y backlog para después del mes.

---

## Reglas de ejecución

- El alcance del MVP se congela al cerrar la Fase 0; las ideas nuevas van al backlog post-mes, no a la semana en curso.
- Si una fase se retrasa, se recorta alcance de la Fase 2, nunca el tiempo de pulido y despliegue de la Fase 3.
- Cada hito se verifica usándolo de verdad, no solo porque el código compile.
